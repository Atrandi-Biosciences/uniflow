# Output definitions specs

This documents handles detailed specs of output files regarding file contents and formats.


# Counts

Each sample holds one `mudata` count file. [Official documentation](https://mudata.readthedocs.io/stable/)

The count file holds any modality that has been generated by the pipeline. The h5mu object can be considered as a collection of anndata, each modality has it's own anndata object.

Modalities can be access by their respective key: `mudata[<modality_key>]`

For example, if the pipeline produced `gene_expression` and `amplicon` modalities, they can be accessed with the following: `mudata["gene_expression"]`

Anndata's documentation can be found [here](https://anndata.scverse.org/en/stable/). We follow their specifications.


# SAM/BAM

We currently use [SAMv1](https://samtools.github.io/hts-specs/SAMv1.pdf) specification.

Additionally we will use optional tags.

For RNA/gene expression we will provide tags provided by STAR:
- CR / UR: Raw (uncorrected) Cell Barcode and UMI sequence.
- CB / UB: Corrected (error-checked) Cell Barcode and UMI sequence.
- GX / GN: Assigned gene ID and gene name.

For DNA/amplicons we will provide the following additional tags:
- CB: Corrected (error-checked) Cell Barcode.

Each bam file will also have it's index `.bai` provided

# Fragments

Fragments is our core information collection for developers and for deep troubleshooting.

Different modalities will have different optional columns but here are the required columns:

- `sample_name`: Name of the sample
- `read_name`: Read name from the original fastq files
- `barcode`: Corrected barcode

# Metrics

The pipeline provides extensive metrics that are collected to `experiment/metrics.csv`

Columns are the following:
- `source_id`: Original of the metric. Can be a sample or a library
- `library_type`: Source of the data, what kind of library type this is
- `modality`: What modality this metrics relates to
- `metric_key`: Machine key id
- `value`: Value of the metric. Because we use polars to generrate those, this column is of type `float64` even for ints.
